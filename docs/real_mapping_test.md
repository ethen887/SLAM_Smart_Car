# 真机栅格地图初步验证

当前瑞萨 3.LSLidar 工程将每个有效 N10 包交给建图模块。STM32 位姿以采样时间戳保留采样间隔，并用 RA 侧串口接收时间估算两板时钟偏移；雷达包使用串口接收中点估算时间，对前后位姿插值，缺少后续位姿时使用最近的较早位姿（最多旧 500 ms）。该方法未进行硬件时钟同步或逐点运动补偿，传感器内部延迟、串口间隔和长期时钟漂移仍会带来误差，需实测确认。

默认地图 300×300 格、0.04 m/格，原点 (-6,-6) m，覆盖 12×12 m；板端以第一帧有效建图位姿为中心，电脑端直接显示 MCU 的闭运算地图快照。原始距离按 mm 转 m，雷达角度按 0.01° 转弧度；0 和 65535 距离被忽略，其他非零距离暂当成命中，需依据雷达协议和实际输出验证过滤规则。雷达安装角和位置偏移默认均为 0；N10 俯视角度顺时针为正，板端将其转换为逆时针为正。可通过 `g_lidar_angle_sign`（+1 或 -1）、`g_lidar_yaw_rad`、`g_lidar_offset_x_m`、`g_lidar_offset_y_m` 调整。停止 CPU 后成组修改，重启会恢复默认值。

在调试器观察 `g_build_map_frames` 是否增长、`g_build_map_skipped_no_pose` 是否变化；`g_build_map_cells` 是地图，启动时清空。停止 CPU 后，可在 GDB 导出完整地图：

```gdb
dump binary memory map.bin &g_build_map_cells[0] &g_build_map_cells[90000]
```

将文件拷贝到电脑后，在仓库根目录运行 `python tools/mapping/render_map_dump.py map.bin map.pgm`；灰色未知、白色空闲、黑色占据。脚本假设 little-endian ARM 的 `Cell` 大小为 12 字节，调试器可用 `p sizeof(Cell)` 验证。图上方向为 X 向右、Y 向上。

雷达和位姿解析器保留跨 DMA 块的不完整帧；队列覆盖及传感器数据质量仍需在硬件验证。无匹配位姿时地图不更新；这不是具有回环校正的 SLAM。


## USB 导航录制与返程

瑞萨与 STM32 必须同时烧录本次固件。运行 `python Renesas/MapBuild_Demo/run_demo.py`，打开“真实数据建图”，连接瑞萨 USB 串口。鼠标放在 Navigation 上展开 Start/End：Start 记录当前自动运行终点，人工带车移动并采样；End 补录当前位置作为自动运行起点，倒序路径并旋转目标航向。总体 Start 启动返程，Stop 急停；“手动控制”取消导航占用、停止录制并释放给原手柄，保留已完成的路线供再次 Start。结束录制、急停、到达终点后仍保持制动，需点击“手动控制”才能继续遥控。路线仅保存于 RAM，重启清空。板端确认、状态、点数和错误在导航状态栏显示。

总体 Start 支持当前位置启动：在地图内寻找最近的剩余路线点，以 100×100、0.12 m/格的四邻域搜索生成接入路径，并在 300×300 细地图上检查碰撞，再逐点返回。完成后再次 Start 可从当前位置重新接入路线。当前位置或目标处于确认占据区域、越界或无连通通路时停车，并分别提示障碍物、地图边界或无法接入录制路线。自动跟踪遇到障碍停车，需主动 Start 重试，不执行绕障重规划。未知栅格允许通行，地图可用范围仍为 -6 至 +6 米。规划及运动检查使用原始占据证据，不依赖电脑绘图。

默认录制间距 0.05 m、转角 0.15 rad；前进上限 0.13 m/s、位置误差速度增益 1.3 s⁻¹（小段路径同样提速约 30%）、角速度上限 0.6 rad/s；车体检查半径 0.15 m，前方检查长度最多 0.20 m，并限制在当前目标距离内；到点后仅原地调整航向。导航占据阈值为 log_odds ≥ 1.5（约 82%），默认单次命中 +0.85 不立即阻挡，重复命中后阻挡；显示地图仍按 log_odds > 0 标黑，因此弱回波可显示但不会立即触发停车。上述为 app_navigation.c 中的初始参数，应根据实际车体尺寸和制动距离调整。路径容量 1000 点，预留终点；满时进入错误状态，需要重新录制。

电脑每 200 ms 发送心跳，板端超过 1 s 未收到心跳或 USB 脱离时暂停；位姿接口超过 500 ms 没有可用数据时暂停。恢复通信和有效位姿后自动继续，自动运行会重新生成接入路径；主动 Stop 保持停止，Start 后恢复。主动“断开”或关闭真实运行窗口会尝试发送 Stop，物理拔线则按失联暂停处理。录制时释放给原手柄控制，自动运行/急停由 STM32 导航接口接管，不被空闲摇杆覆盖。STM32 超过 350 ms 未收到运动命令时制动，恢复收到新命令后继续。

内部 USB 帧使用 A5 5A、uint16 小端负载长度、负载、CRC16/MODBUS（长度字段至负载末尾）。命令负载为 `N,1,command,sequence`，command 1/2/3/4/5/6 为录制开始/结束/运行/急停/心跳/手动控制。状态负载为 `N,1,command,sequence,state,error,count:uint16,target:uint16`。状态周期 500 ms，操作后也发送确认。电脑无需手动构造协议。板间沿用 AA 55 串口帧，类型 0x20，负载 mode:uint8、v:float32、w:float32，mode 0 释放手柄、1 控制运动、2 制动；其 CRC 和帧尾沿用现有 STM32 协议。

主机闭环测试使用模拟位姿和电机输出，覆盖近边界目标转身返程、到点航向调整不前进、弱命中与确认占据、边界和无通路分别报告、录制反转、偏离起点后接入路线、完成、急停锁存、位姿及通信恢复、容量和错误 CRC；STM32 测试覆盖轮速换算、命令超时、制动与手动控制释放。界面测试创建 Tk 窗口验证悬停菜单、按钮与状态反馈。真实 USB 收发、实际轮向、车体间隙和跟踪精度仍需板上联调；当前定位依赖里程计，没有地图匹配或回环修正。


地图快照当前为版本 5：300×300 个 2-bit 状态，共 22525 字节（含帧头、位姿及 CRC），维持约 200 ms 发布周期。电脑可同时解析旧版本 3 的 100×100 和版本 4 的 300×300 快照（均为 6×6 m）。墙体分类队列使用 uint32 索引以覆盖 90000 格；USB 发送环形缓冲扩大为 32768 字节。帧内 marks 与快照临时数组在同一线程分时复用；不可将地图更新与快照处理改为并行调用而不重新分配或同步。

300×300 刷新优化：单包证据写回限定在射线包围区域；USB 以 2048 字节分块、环形缓冲使用连续复制，并在发送容量不足时跳过快照计算。电脑使用查表 CRC、按行段合并障碍物边框、复用 Matplotlib 图像与图层。接收线程只保存最新一张地图，导航状态独立排队；心跳在串口线程每 200 ms 发送，避免绘图阻塞导致误判失联。保持 300×300、0.04 m/格及快照 v5 格式。实际刷新率和遥控需烧录新版瑞萨固件并重启电脑界面后实测，USB CDC 波特率设置不会改变 USB 总线速率。
