# USART1 里程计通信协议

## 连接与约定

USART1：PB6 TX、PB7 RX，115200 baud、8N1、无流控。TX 使用 DMA1 Channel 4 Normal；RX 使用 DMA1 Channel 5 Circular；两个 DMA 和 USART1 全局中断均启用。多字节整数均小端，浮点数为 IEEE 754 binary32 小端。线路收发连接需共地并使用匹配的 3.3 V 电平。

每条有效里程计都是独立帧：

| 偏移 | 大小 | 内容 |
| --- | --- | --- |
| 0 | 2 | 帧头 `AA 55` |
| 2 | 1 | 消息类型，里程计为 `01` |
| 3 | 2 | 负载长度，小端；里程计为 `10 00`（16 字节） |
| 5 | 4 | `uint32` 采样时间戳，单位 ms |
| 9 | 4 | `float32 x`，m |
| 13 | 4 | `float32 y`，m |
| 17 | 4 | `float32 heading`，rad |
| 21 | 2 | CRC-16/MODBUS，低字节在前 |
| 23 | 2 | 帧尾 `0D 0A` |

CRC 参数：初值 `FFFF`，反射多项式 `A001`，输入输出反射，异或输出 `0000`；校验范围从消息类型到负载末尾（偏移 2～20），不含帧头、CRC 和帧尾。标准检验字符串 `123456789` 的 CRC 为 `4B37`。

`x/y/heading` 是连续局部 odom 坐标：初始车头为 +X，初始左侧为 +Y，逆时针为正；航向范围 [-π, π)。当前实现可能融合 IMU，并非始终是纯编码器数据。时间戳为采样周期开始时读取的 STM32 HAL 毫秒计数，不是上位机时间或发送时间；32 位约 49.7 天回绕，重启后重新开始。上位机要处理回绕、重启和时钟对应；精确雷达同步还需后续实现时钟同步及评估采样时差。

## 发送

移动任务每次有效更新后生成一帧；无效更新跳过。20 帧的环形队列满时覆盖最旧的待发送完整帧，计入 `host_comm_stats.tx_overwritten`。通信任务在至少有 5 帧且 DMA 空闲时，将最旧 5 帧复制到独立的 125 字节缓冲区，并启动一次 DMA 发送；发送完成之前缓冲区不修改。启动失败会保留该批次重试，不足 5 帧一直等待。上位机接收到的是连续字节流，不应假设一次读取恰好是 125 字节或一帧。

上位机按帧头和长度定位帧，再校验 CRC 和帧尾；非法帧逐字节重同步。二进制负载内部也可能包含帧头或帧尾，不能仅靠标记分包。协议没有序号，无法准确统计串口和上位机端丢帧；STM32 端覆盖计数可在调试器中查看。

## 接收与扩展

接收使用 128 字节循环 DMA，半满、满和 UART 空闲事件在中断中仅复制新字节到 256 字节软件环形缓冲；通信任务负责拆帧和校验。软件接收缓冲溢出时丢弃旧的未处理字节、计数并重新同步。单帧负载上限为 64 字节，头、类型、长度、CRC、尾格式与上面相同，CRC 覆盖类型、长度和负载。解析成功后调用 `App_HostComm_OnFrame(type, payload, length)`；当前默认实现不执行任何命令。未来可定义下行消息类型并覆盖此弱函数；payload 只在回调期间有效。地图修正的内容、时间对应和应用规则尚未定义，当前不会修改里程计或驱动电机。

`host_comm_stats` 包含发送覆盖、启动错误、DMA 发送错误、发送批次，以及接收溢出、错误、无效帧和有效帧计数。DMA 异常发生后接收会重新启动，异常期间的数据不保证保留。

## 测试

主机测试（需要 gcc）：

```sh
gcc -std=c11 -Wall -Wextra -I tools/tests/host_comm -I STM32_F103/App tools/tests/host_comm/test_host_comm.c STM32_F103/App/app_host_comm.c STM32_F103/App/host_protocol.c -o host_comm_test
./host_comm_test
```

固件编译通过不等于硬件已验证：需要实际连接上位机，检查连续上报、CRC、环形缓冲溢出、接收分帧及长时间运行。CubeMX 重新生成后应核对 DMA 配置、USART1/DMA 中断、`freertos.c` 用户代码区和构建文件。
