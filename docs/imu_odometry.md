# IMU 姿态、里程计与后续 SLAM 对接

## 当前实现

- 坐标约定：车体 X 前、Y 左、Z 上，右手系；里程计起始车头为 odom X，向左为 odom Y，逆时针航向为正。距离使用 m，角度使用 rad，时间使用 s。
- `app_attitude.c` 按 FIFO 顺序读取原始 SI 单位样本，用四元数积分三轴陀螺仪；接近 1g 时用加速度修正横滚和俯仰。六轴 IMU 无法观测绝对航向，因此 yaw 是相对角度，会随时间漂移。无硬件磁力计，不应把 yaw 当成罗盘值。
- 开机必须让轮子及车体静止约 2 秒，累计 200 个满足静止和重力条件的陀螺仪样本后计算零偏。校准前里程计仍以编码器运行；移动或重力异常会重新开始计数。完成校准时 yaw 从零开始。FIFO 数据流中断恢复后姿态重新依据重力初始化，yaw 的参考会重置，但校准零偏保留；不会跨中断积分。
- 硬件装配方向尚未得到确认。默认传感器 XYZ 分别等于车体 XYZ；请在 `app_attitude.c` 的 `IMU_BODY_X/Y/Z` 设置有符号的轴号（1、2、3 分别是传感器 X、Y、Z），且必须构成右手系。加速度和陀螺仪共用此转换。以车体水平静止时 Z 接近 +9.81 m/s²、逆时针水平旋转时 Z 角速度为正进行检查。安装方向错误会使姿态和里程计错误。
- `odometry_data` 为连续本地 odom 位姿：轮增量给出距离，陀螺仪和左右轮转角按 `odometry_gyro_weight` 混合（默认 0.8，可在调试器中调整到 0～1）；加速度不直接做位置积分。`heading_delta` 仍是原始编码器转角，`fused_heading_delta` 是实际积分的转角，`imu_used` 标记当前周期是否采用 IMU。姿态算法使用原始样本；RAM 日志中低通数据仍用于诊断，不作为该算法的输入。
- 当未校准、FIFO 错误/积压、采样间隔不匹配、周期过长或数据无效时，该周期使用纯编码器。使用样本平均角速度按控制周期重采样；104 Hz IMU 与约 100 Hz 轮速并不同步，FIFO 未提供精确采样时间戳，这只是当前阶段的近似，不是严格时间同步。空采样周期退回编码器；速度快、FIFO 积压或时间抖动时精度需要实测。
- 默认轮半径、轮距和方向来自当前实验配置，必须实测核对；这里的融合不解决轮胎打滑、尺度误差、IMU 振动或长时间漂移。

## 板上检查

1. 固定好 IMU，核对轴向和编码器方向，断电后重启并保持静止。观察 `lsm6dsr_init_result`、`lsm6dsr_fifo_debug.status`、`attitude_data.calibration_samples/calibrated`，等待校准完成。
2. 手动小角度倾斜车体并检查 `attitude_data.roll/pitch` 的方向，再低速原地左转和右转，核对 `attitude_data.yaw` 和 `odometry_data.heading` 的正负；同时观察 `imu_used`、`heading_delta` 和 `fused_heading_delta`。无法确认方向前不要使用自主运动。
3. 检查 IMU FIFO 是否经常报错、溢出或积压；检查 `move_task_dt_s`、控制任务栈高水位和系统稳定性。姿态计算在运动任务执行，增加了计算和栈开销，目标板的时序和栈余量仍需实际测量。
4. 移动期间断开或模拟 IMU 失败时应看到 `imu_used=false` 且位姿仍由编码器更新；重新恢复后不应把丢失的陀螺仪积分补入。绝对精度应以后通过独立距离/角度测量标定。

## 后续 UART / SLAM 约定

当前仅准备了融合结果和纠正 API，**没有实现板间 UART 收发或指定协议**。现有 USART1 为 PB6 TX、PB7 RX、115200 8N1；是否用于板间通信、引脚接线和上层接口需两板共同确定。不可把调试发布时刻当作 IMU 硬件采样时刻。

保留 `odom` 为连续局部坐标系：上层发送某时刻的地图位姿 `map_pose`，同时提供该时刻对应的 `odom_pose_at_measurement`；在运动任务调用 `App_Odometry_SetMapCorrection(map_pose, odom_pose_at_measurement)`，计算 `map_T_odom = map_T_body * inverse(odom_T_body)`。`App_Odometry_GetMapPose` 再将最新 odom 位姿变换到地图坐标。历史位姿和地图位姿必须对应同一时刻；不能将延迟到达的 SLAM 位姿与收到时的当前 odom 位姿配对，否则会引入延迟误差。重置 odom 会清除此变换，需重新建立。

未来 UART 帧至少应包含版本、类型、长度、序列号、时间基准/时间戳、数据有效状态、校验，并明确小端及数值单位。上行建议携带连续 odom 位姿、速度、IMU 状态和采集时间；下行携带 SLAM 位姿及其对应的 odom 时间/位姿，并处理乱序、超时、复位及时钟同步。中断只负责缓存数据，解析与调用纠正 API 放在运动任务或通过受保护队列交接；当前各接口仅保证同一任务使用，跨任务读取结构体需同步。未来通信代码必须处理 DMA/中断发送缓冲区所有权，不能在发送未完成时覆盖缓冲区。
